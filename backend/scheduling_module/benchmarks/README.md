# مجموعه‌های داده‌ی آزمون و پاسخ مرجع (Benchmark Seeds & Ground Truth)

این پوشه پنج مجموعه‌ی داده‌ی آماده برای **ارائه و ارزیابی** الگوریتم زمان‌بندی
(BBO + گرگ خاکستری) را نگه می‌دارد. هر مجموعه یک نیمسال کامل و ساختگی است و در
کنار آن یک **پاسخ مرجع** (ground truth) ذخیره شده است: زمان‌بندی‌ای که هیچ
محدودیتی را نقض نمی‌کند و هزینه‌ی آن صفر است.

## جریان کار در برنامه

۱. **داشبورد → تب «داده‌های آزمون»** — پنج مجموعه با آمار و توضیح نمایش داده می‌شود.
۲. **«مشاهده داده‌ها و پاسخ مرجع»** — اساتید، دروس، مکان‌ها، گروه‌ها، محدودیت‌ها و
   جدول هفتگیِ پاسخ مرجع را به کاربر نشان می‌دهد (برای ارائه به مخاطب).
۳. **«بارگذاری در برنامه»** — یک `UniversityConfig` جدید با همه‌ی رکوردها ساخته و
   **فعال** می‌شود، به‌همراه یک وظیفه‌ی زمان‌بندی آماده‌ی اجرا.
۴. **تب «زمان‌بندی هوشمند» → اجرا** — الگوریتم روی همان داده اجرا می‌شود.
۵. **«مقایسه با پاسخ مرجع»** — گزارش کامل ارزیابی نمایش داده می‌شود.

از خط فرمان هم می‌شود همین کار را کرد:

```bash
python manage.py load_benchmark_seed --list
python manage.py load_benchmark_seed seed_02_computer_engineering --user admin
python manage.py load_benchmark_seed --all --user admin
```

و برای اجرای الگوریتم و گرفتن عدد بدون نیاز به دیتابیس و رابط کاربری:

```bash
python -m scheduling_module.benchmarks.run_benchmark --repeats 3
python -m scheduling_module.benchmarks.run_benchmark seed_05_large_faculty --popsize 80 --maxgen 300
```

## پاسخ مرجع چگونه ساخته می‌شود؟

`solver.py` یک **جست‌وجوی کامل با پس‌گرد** (backtracking با MRV پویا و شروع مجدد
تصادفی) است و هیچ ارتباطی با الگوریتم فراابتکاری ندارد. این استقلال عمدی است:
اگر پاسخ مرجع را با خودِ الگوریتم می‌ساختیم، مقایسه بی‌معنا می‌شد.

`generate_seeds.py` پس از یافتن جواب، سه بررسی انجام می‌دهد و تنها در صورت عبور
از هر سه، فایل JSON را می‌نویسد:

1. ارزیاب تفکیکی (`evaluation.evaluate_entries`) باید **صفر تخلف** گزارش کند.
2. تابع هزینه‌ی **خودِ الگوریتم** (`HybridBBO_RL_Scheduler._fitness`) باید **صفر** بدهد.
3. همه‌ی `time_preference`ها باید رعایت شده باشند.

بازتولید فایل‌ها (مثلاً پس از تغییر تابع هزینه):

```bash
python -m scheduling_module.benchmarks.generate_seeds
```

## گزارش مقایسه چه چیزی را می‌سنجد؟

گزارش عمداً **دو بخش مستقل** دارد، چون مسئله‌ی زمان‌بندی هزاران جواب بهینه دارد و
پاسخ مرجع فقط *یکی* از آن‌هاست:

**۱) کیفیت (ملاک داوری).** تعداد تخلف‌های تفکیک‌شده و هزینه‌ی خروجی در برابر مرجع.
داوری نهایی فقط بر این اساس است:

| کد داوری | معنا |
|---|---|
| `identical` | خروجی دقیقاً همان پاسخ مرجع است |
| `equivalent_optimal` | جدول متفاوت ولی بدون هیچ تخلفی — یک جواب بهینه‌ی دیگر |
| `near_optimal` | حداکثر ۳ تخلف جزئی |
| `suboptimal` | بیش از ۳ تخلف |
| `incomplete` | تعداد جلسات با مرجع نمی‌خواند (داده‌ی نیمسال دستکاری شده) |

**۲) شباهت (فقط برای نمایش).** چند درصد از جلسات مثل پاسخ مرجع چیده شده‌اند.
جلسات یک درس با هم قابل جابه‌جایی‌اند، بنابراین برای هر درس **بهترین تناظر
یک‌به‌یک** بین جلسات مرجع و خروجی محاسبه می‌شود، نه مقایسه‌ی سطر به سطر.

⚠️ انتظار نداشته باشید این درصد بالا باشد: یک خروجی کاملاً بی‌نقص هم معمولاً فقط
۵ تا ۱۵ درصد انطباق کامل با این جدول خاص دارد. برای همین بخش **«توزیع بار»** هم
گزارش می‌شود (تعداد جلسات در هر روز/بازه/استاد/مکان) که برای دو جواب بهینه‌ی
متفاوت معمولاً بالای ۸۵٪ شبیه است و معیار گویاتری برای ارائه است.

## ساختار فایل‌ها

| فایل | نقش |
|---|---|
| `definitions.py` | تعریف داده‌های خام پنج مجموعه (تنها جایی که برای تغییر داده‌ها ویرایش می‌شود) |
| `solver.py` | حل‌کننده‌ی دقیق برای ساخت پاسخ مرجع |
| `generate_seeds.py` | ساخت + اعتبارسنجی + نوشتن فایل‌های `seeds/*.json` |
| `config_builder.py` | تبدیل seed به پیکربندی الگوریتم (هم‌شکل با `_build_config_from_db`) |
| `evaluation.py` | ارزیابی تفکیکی تخلف‌ها + محاسبه‌ی هزینه‌ی رسمی الگوریتم |
| `comparison.py` | موتور مقایسه‌ی خروجی با پاسخ مرجع |
| `db_loader.py` | ساخت `UniversityConfig` و رکوردها از روی seed |
| `run_benchmark.py` | اجرای الگوریتم و گزارش متنی، بدون Django |
| `seeds/*.json` | مجموعه‌ها + پاسخ مرجع (تولیدشده — دستی ویرایش نکنید) |

## API

| متد | مسیر | کار |
|---|---|---|
| GET | `/scheduling/api/benchmarks/seeds/` | فهرست مجموعه‌ها با آمار |
| GET | `/scheduling/api/benchmarks/seeds/<key>/` | داده‌های کامل + پاسخ مرجع |
